# 03 程序结构与启动类配置（速查）

> 蒸馏来源：《火山视窗全栈开发技能书》V2.6（第1/4/7/11.1/15/16章）、《火山视窗模块信息.md》、《火山视窗项目文件格式技术规范.md》。
> 覆盖：wsv 文件结构、包定义、类定义与归属、启动类 4 种基础类、启动方法、主窗口成员变量规则、.vprj/.vsln 关键字段、.vgrp 模块定义文件格式。

## 一、wsv 文件整体结构与成员归属

### 1.1 文档声明行（首非空行必须）

火山平台将源程序以 **UTF-8 编码文本格式** 保存，文件后缀为 **`.wsv`**。wsv 文本程序数据分两种：**完整程序数据**（保存完整火山程序，可直接编译运行）、**剪切程序数据**（保存复制到剪贴板中的程序片段）。**首非空行必须是文档格式和版本定义行**：

```wsv
<火山程序 类型 = "通常" 版本 = 1 />
```

| 属性 | 取值 | 说明 |
|------|------|------|
| 类型/type | `通常` / `normal` | 当前火山程序文档的格式类型 |
| 版本/version | `1` | 目前最新版本号 |

> **易错点**：首行必须严格为声明行，否则解析器无法识别文件格式，IDE 会报"文件格式错误"。漏写或写错（如把 `版本` 写成 `version` 之外的值）同样报"文件格式错误"。

### 1.2 整体结构（成员归属位置）

```
文档声明行
包定义（唯一，必须位于首部）
  ├── 文档注释行 / 文档嵌入行
  └── 类定义                        ← 类必须位于文档顶层（包定义之下），不能嵌套在其它类/方法内
        ├── 类嵌入行 / 类注释行
        ├── 类成员常量
        ├── 类成员变量
        └── 类成员方法
              ├── 方法参数
              ├── 方法局部常量
              ├── 方法局部变量
              ├── 语句注释行
              ├── 语句嵌入行
              └── 火山语句行
```

参考代码：

```火山代码
<火山程序 类型 = "通常" 版本 = 1 />

包 火山.视窗.ELK引擎

类 ELK引擎类 <公开 注释 = "★ 本类由\"飞翔的企鹅\"封装." @视窗.外部头文件 = "lib\\elk_vol.h">
{
    #
    常量 成员常量1 <类型 = 整数 值 = 123>
    变量 成员变量1 <公开 类型 = 整数 值 = 123>

    方法 执行 <公开 类型 = 文本型 注释 = "执行指定的JavaScript代码并返回其执行结果." @嵌入式方法 = "">
    参数 内容 <类型 = 文本型 注释 = "提供所欲执行的JS代码内容">
    {
        常量 局部常量 <类型 = 整数 值 = 123>
        变量 局部变量1 <类型 = 整数 值 = 111>
    }
}
```

### 1.3 各成员定义格式

| 类型 | 语法格式 | 支持的属性 |
|------|---------|-----------|
| 包 | `包/package 包名称 [属性表]` | 注释、折叠2、@外部包 等 |
| 类 | `类/class 类名称 [属性表] { 类定义体 }` | 公开、基础类、注释、折叠、折叠2 等 |
| 方法 | `方法/method 方法名称 [属性表] [参数表]... { 子语句体 }` | 公开、静态、定义事件、接收事件、属性读、属性写、类型、注释、返回值注释 等 |
| 参数 | `参数/param 参数名称 [属性表]` | 类型、注释、折叠 等 |
| 常量 | `常量/const 常量名称 [属性表]` | 公开、类型、值、注释 等 |
| 变量 | `变量/var 变量名称 [属性表]` | 公开、静态、参考、类型、值、注释 等 |
| 注释/嵌入行 | `# [属性表] 注释/嵌入行内容` | - |
| 语句行 | `[属性表] 语句行内容 { 子语句体 }` | 折叠 |

**成员名称** 如果不为有效的单/全名称文本，就必须使用以双引号括住的转义字符串格式。所有以花括号括住的代码块若内容为空，则整个花括号代码块可被省略。

### 1.4 名称规则

| 名称类型 | 规则 |
|---------|------|
| 单名称 | 以英文字母/下划线/汉字开头，后跟字母/下划线/数字/汉字 |
| 全名称 | 以句点组合多个单名称，如 `火山.程序` |
| 标识符名称 | 多个单词 + 版本号，如 `cplus.win32.console.1` |

**注意**：火山中的名称对英文字母的大小写敏感，`abc` 与 `ABC` 不是同一名称。

## 二、包定义规则

**包名必须为全名称**（由多个单名称以句点组合），一个包内可包含多个文档注释行/文档嵌入行/类定义。

```wsv
包 火山.视窗.网络
```

| 规则 | 说明 |
|------|------|
| 唯一 | 包定义成员始终位于源文件首部，且**只能存在一个** |
| 同名合并 | 多个程序文件可具有相同的包名，此时其内容被视为处于同一个包中 |
| @外部包 | 包定义支持 `@外部包` 属性（允许多设置项），用于指定在本源文件内优先查询的外部包名列表，解决类名冲突 |

## 三、类定义与归属位置

### 3.1 基本属性

```火山代码
<火山程序 类型 = "通常" 版本 = 1 />

类 测试类 <公开 基础类 = 窗口>
{
    #
}
```

| 属性 | 说明 |
|------|------|
| 基础类 | 指定本类的基础类名称，可为空文本（表示无基础类）。定义非空基础类后自动继承其所有内容。名称为"启动类"的类用作特定定义用户程序的启动类 |
| 公开 | 公开类可以在所处包外部被访问，非公开类只能在包内被访问 |

**继承类访问基础类中的成员不需要其为公开状态。**

### 3.2 类特殊属性速查

| 属性 | 说明 |
|------|------|
| @常量类 | 指定类是否为常量类及其对应的基本数据类型。类中只允许定义数据类型为该类的常量成员（类型为空时自动默认为所处常量类）；常量类的基础类只能是常量类（对应基本数据类型必须一致）；数据类型为常量类的局部变量访问前必须首先明确赋值；常量类不能与对应基本数据类型匹配，但可强制转换 |
| @类用途 | 指定类允许的具体用途：1.通常（作为通常的数据类型使用，默认）；2.禁止创建对象；3.定义嵌入参数类型（不允许定义除嵌入式方法参数之外成员，"假"别名类）；4.访问静态成员（只能用作访问类中的静态/常量成员，实现"命名空间"作用） |
| @别名 | 别名类直接封装所指定的目标语言本地类。只允许定义常量/变量/静态方法成员；成员变量必须指定@输出名（假变量）；可为其它非别名类的基础类 |
| @别名类型 | 别名类的具体类型：1.火山类（默认，C++从CVolObject类继承）；2.本地类（如C++ class）；3.本地结构（如C++ struct）；4.本地整数基本类型（须提供"有效值范围"属性）；5.本地值类型；6.本地参考类型（不支持C++参考，支持指针） |
| @全局类 | 全局类中的所有静态公开方法在外部访问时都可以**省略其类名指定**（嵌入行语句中除外），此类方法被称为**全局方法** |
| @本地类 | 编译时不附加任何火山对象类的额外信息。不能是别名类或常量类，不能具有基础类；类中不能定义通常火山程序类的非参考成员变量，不能定义事件/虚拟方法 |
| @模板基础类 / @模板实现类 | 模板基础类：只能用作模板实现类或其它模板基础类的基础类，只有在此类中才能使用模板数据类型（模板类型1~8）；模板实现类：基础类必须为模板基础类，本属性值顺序提供所有模板数据类型的实际替换数据类型 |
| @默认基础类 | 当其它类（不包括常量类）没有指定基础类时，使用该类作为默认基础类。整个应用程序中只允许一个；该类不允许定义有基础类、不允许为常量类；必须确保其为所有外部本地类的实际基础类，且定义有无参数构造方法 |

@常量类 对应数据类型选择项：字节、短整数、字符、整数、变整数、长整数、单精度小数、小数、逻辑型、文本型、文本到ID。

| 属性 | 说明 |
|------|------|
| @禁止创建对象 | 不允许用作定义常量/变量（参考变量/数组变量除外）的数据类型 |
| @禁止静态 | 是否允许定义该类及其所有继承类的静态或静态参考变量 |
| @禁止继承 | 是否不允许本类作为其它类的基础类 |
| @虚拟方法 | 指定方法为虚拟方法，可选"可覆盖/不可覆盖" |
| @自动挂接事件 | 是否自动将该类或类对象支持的所有事件挂接到本类上（默认真） |
| @属性变量 | 指定非静态类成员变量是否为其所处类的属性型成员 |
| @输出名 | 指定编译后的输出名称 |
| @废弃 | 标记该类或方法已被废弃（警告/错误） |
| @强制输出 | 指定类/方法将被强制编译输出 |
| @强制依赖 | 强制指定一个或多个类为本类/方法的依赖类 |

### 3.3 事件机制要点（类成员变量与事件接收）

- 非静态的类成员变量，如果其数据类型为类且其中定义有事件，将被**自动挂接**到当前类实例对象；类的静态成员变量**不支持自动挂接**事件，需要时可用 `挂接事件` 命令手动挂接；可通过 `@自动挂接事件` 属性（类或类的非静态成员变量）控制，默认值为真。
- 动态创建的窗口/组件也需用 `挂接事件 (窗口1)` 挂接后其事件才能被接收（动态创建库官方注释写法）。
- 常规设计窗口中的控件成员变量为**非静态成员变量**时自动挂接事件，无需手动调用本命令。

```火山代码
挂接事件 (取程序 ().数据库1)   // 将"数据库1"对象的事件挂接到当前类
```

- 接收方法中第 2 个参数 `标记值` 接收调用本命令时提供的"标记值"参数值；未通过本命令挂接（即自动挂接）时该参数值固定为 0。
- 自定义类需要支持事件时，可持有一个 `事件发送器` 对象并挂接 `事件接收器` 对象（见 6.1 节）：
  - `事件发送器.挂接 (所欲挂接的接收器)`：将 `事件接收器` 对象挂接到本发送器，先前的挂接将被覆盖；
  - `事件发送器.取消挂接 ()`：取消当前已挂接的接收器（接收器对象被销毁时自动取消，通常无需显式调用）；
  - `事件发送器.是否已挂接 ()`：返回当前是否已挂接接收器；
  - `事件发送器.发送事件 (事件参数, 事件返回值, 事件附加对象, 事件附加值)`：向已挂接的接收器发送事件，返回其"接收到事件"事件方法的返回值，未挂接时返回 0。
- 事件接收方定义 `接收到事件` 方法即可接收并处理事件。

```火山代码
方法 按钮_被单击 <接收事件>
参数 来源对象 <类型 = 按钮>
参数 标记值 <类型 = 整数>
{
    // 处理按钮单击事件
}
```

**方法名称格式**必须为：`事件所属类名 + "_" + 事件名`（如 `按钮_被单击`、`时钟_周期事件`）。

## 四、启动类与启动方法

### 4.1 启动类定义

名称为"启动类"的类用作特定定义用户程序的**启动类**（程序入口）。

### 4.2 启动类基础类的 4 类继承链

| 类名 | 基础类 | 所属模块 | 说明 |
|------|--------|---------|------|
| `程序类` | 程序基础类 | 火山.基本 | 所有程序启动类的根基类。`@禁止创建对象` |
| `窗口程序类` | 程序类 | 火山.基本 | 基于窗口的用户程序启动类。`@禁止创建对象`。提供三个可覆盖虚方法 |
| `动态库程序类` | 程序类 | 火山.基本 | 动态链接库程序的启动类。`@禁止创建对象` |

继承链：**程序基础类 → 程序类 → {窗口程序类, 动态库程序类}**。

| 类名 | 提供的成员 |
|------|-----------|
| `程序类` | 提供 `取用户程序版本号`(小数)、`取火山平台版本号`(整数)、`取用户程序版本名`(文本型) 等静态方法 |
| `窗口程序类` | 提供 `消息过滤`、`空闲`、`即将退出` 三个可覆盖虚方法 |
| `动态库程序类` | 提供 `入口通知`、`将被卸载` 等可覆盖虚方法 |

> **注意**：`消息过滤`/`空闲`/`即将退出` 是可直接覆盖的虚方法，覆盖实现时**不要**标注 `<接收事件>`（它们不是事件，与 3.3 节的事件接收方法不同）。

### 4.3 基础类选择规则

| 程序形态 | 启动类基础类 | 依据 |
|---------|-------------|------|
| 界面程序（MFC/WTL） | 继承 `窗口程序类` | 7.1：界面程序启动类必须继承 `窗口程序类`；负责创建窗口与消息循环 |
| 控制台/无窗口程序 | 直接继承 `程序类` | 7.1：控制台/无窗口程序启动类直接继承 `程序类`；11.1：控制台程序基础类为"程序类" |
| 动态链接库程序 | 继承 `动态库程序类` | 7.1/7.2：动态链接库程序的启动类 |

- **没有"控制台程序类"**：全书 11 处"控制台程序类"均已修正为"程序类"，11.1 依官方 console demo 重写（V2.5修正）。
- **易错点**：界面程序若误继承"程序类"而不是"窗口程序类"，将不会自动建立窗口和消息循环；控制台程序若误继承"窗口程序类"，程序将按窗口程序方式运行。

### 4.4 启动方法

- 启动方法必须位于启动类中，通常返回整数；系统调用入口。
- 官方 console demo 以 `返回 (1)` 结束程序；窗口程序返回 0；7.1 最小窗口程序示例中创建主窗口失败返回 -1。
- 新建视窗项目后，IDE 自动生成主源文件 `src\main.wsv`，其中包含启动类与启动方法（15.5）。

### 4.5 窗口程序类可覆盖虚方法（启动类可覆盖）

| 方法名 | 返回值 | 虚方法 | 说明 |
|--------|--------|--------|------|
| `消息过滤` | 逻辑型 | 可覆盖 | 过滤处理程序中所有窗口的消息。返回真允许继续传递，返回假取消。参数：窗口句柄(变整数)、消息值(整数)、消息参数1(变整数)、消息参数2(变整数)、消息地址(变整数) |
| `空闲` | 逻辑型 | 可覆盖 | 系统空闲时调用。参数：已空闲时间(整数，单位毫秒)。返回假则本次空闲期间不再调用（降低CPU占用），返回真则继续调用 |
| `即将退出` | - | 可覆盖 | 窗口程序退出前调用，用于执行清理工作（释放资源、保存配置等） |

### 4.6 程序类的静态方法

| 方法名 | 返回值 | 静态 | 说明 |
|--------|--------|------|------|
| `取用户程序版本号` | 小数 | 是 | 返回项目设置中设定的程序版本号 |
| `取用户程序次版本号` | 小数 | 是 | 返回项目设置中设定的程序次版本号 |
| `取用户程序版本名` | 文本型 | 是 | 返回项目设置中设定的程序版本名称文本 |
| `取火山平台版本号` | 整数 | 是 | 返回编译此程序时所使用的火山平台版本号 |

### 4.7 窗口类的创建方法

| 方法名 | 返回值 | 说明 |
|--------|--------|------|
| `创建窗口` | 逻辑型 | 创建本窗口类的对象（非主窗口）。参数均可省略，省略时使用设计时默认值 |
| `创建有菜单窗口` | 逻辑型 | 创建窗口，第一参数指定菜单类的数据类型（`@需求类型`:"数据类型"） |
| `创建主窗口` | 逻辑型 | 创建并设为主窗口。程序必须且只能存在一个主窗口。**主窗口必须在启动类中定义为成员变量** |
| `创建有菜单主窗口` | 逻辑型 | 创建带菜单主窗口，第一参数为菜单数据类型 |
| `置为主窗口` | - | 将已有窗口对象设置为主窗口（不再调用创建主窗口） |
| `创建子窗口` | 逻辑型 | 创建为其他窗口的子窗口（非主窗口），显示内容位于父窗口之上且被裁剪 |
| `创建弹出子窗口` | 逻辑型 | 创建为弹出风格子窗口（非主窗口），显示内容独立存在且不被父窗口裁剪 |
| `创建对话框` | 整数 | 以模态对话框方式创建并显示，等待关闭后返回。不能动态调整尺寸/位置，初始居中。返回值为调用 `关闭窗口` 时提供的结果值；Alt+F4/ESC/关闭按钮关闭则返回-1 |

## 五、主窗口成员变量规则

- 主窗口对象必须是启动类中的**成员变量**（不能是 `启动方法` 中的局部变量），否则窗口创建后对象析构导致崩溃（7.1）；例外：`创建对话框` 方式创建的窗口对象**可以是局部变量**（`创建对话框` 是同步阻塞的，返回后窗口已关闭）。
- 程序中只能存在一个主窗口（`创建主窗口` 或 `置为主窗口` 只能调用一次）。
- 参考变量写法（11.2）：`主窗口对象 <参考 = 真>` 仅作引用，由系统创建窗口实例。
- 7.1 最小窗口程序示例中成员变量无 `参考` 属性：`变量 主窗口对象 <类型 = 主窗口>`。
- 控件成员变量：数据类型为控件类，非静态成员变量**自动挂接**该控件的事件（11.2）。

## 六、完整代码示例

### 6.1 控制台程序最小示例（参考官方 console demo（包名火山.测试），11.1）

一个视窗控制台项目只需一个源文件 `main.wsv`：

```火山代码
// ① 文档首非空行：声明本文件为火山程序，类型"通常"，格式版本1
<火山程序 类型 = "通常" 版本 = 1 />

// ② 包定义：必须位于文件首部且只能有一个，包名为全名称（官方 console 示例包名为"火山.测试"）
包 火山.测试

// ③ 启动类：名称为"启动类"的类用作程序启动入口；控制台程序基础类为"程序类"
类 启动类 <公开 基础类 = 程序类>
{
    // ④ 启动方法：程序入口，返回整数
    方法 启动方法 <公开 类型 = 整数>
    {
        // ⑤ 提示并读取第一个加数：标准输出 输出提示文本，标准输入 读取一行文本，文本到小数 将其转换为小数
        标准输出 (, "请输入加数1：")
        变量 变量1 <类型 = 小数>
        变量1 = 文本到小数 (标准输入 ())

        // ⑥ 提示并读取第二个加数
        标准输出 (, "请输入加数2：")
        变量 变量2 <类型 = 小数>
        变量2 = 文本到小数 (标准输入 ())

        // ⑦ 输出计算结果：到文本 将小数转换为文本后拼接输出
        标准输出 (, "相加结果为：" + 到文本 (变量1 + 变量2))

        // ⑧ 等待任意按键后退出
        标准输出 (, "按任意键退出...")
        标准输入字符 ()
        返回 (1)
    }
}
```

知识点：`标准输出`/`标准输入` 为控制台程序的标准输出与标准输入（发布版运行时同样可用）；`标准输入 ()` 读取一行文本；`文本到小数` 将文本型转换为小数；`到文本` 将数值转换为文本；`返回` 从方法返回值（官方 demo 返回 1 结束程序）。

运行效果（假设输入 3 和 5）：

```
请输入加数1：3
请输入加数2：5
相加结果为：8
按任意键退出...
```

易错点（11.1）：
- **标准输出 与 调试输出 的区别**：`标准输出` 输出到控制台窗口（发布版可见）；`调试输出` 仅显示在 IDE 调试输出窗口，发布版默认不显示；
- **输入转换**：`文本到小数`/`文本到整数` 转换失败（输入非数字）时结果不可靠，正式程序应校验输入；
- 名称大小写敏感，`变量1` 与 `变量2` 是不同变量。

## 七、项目文件（.vprj）关键字段

`.vprj` 定义单个 Windows 应用的完整配置，**UTF-8 编码**（读写必须使用 UTF-8，否则解析错误）。

### 7.1 文件头与 project_identifier

```
doc_format_version = 1
project_identifier = "wutao.vproject.pc.win.1"
```

| 字段 | 固定值 | 说明 |
|------|--------|------|
| `project_identifier` | `wutao.vproject.pc.win.1` | Windows 桌面应用项目标识符，IDE 据此加载对应的构建工具链 |

**注意事项**：该标识符为固定值，AI 生成或手写 `.vprj` 时不得改动；写错会导致 IDE 无法识别项目类型。

### 7.2 settings.project 设置项（16.1）

```
settings
{
    project
    {
        result_type = 2          // 2 = EXE（可执行文件），1 = DLL
        target_platform = 1      // 1 = Win32，2 = x64
        out_file_name = "..\\out\\$(p)\\test.exe"
        debug_command_line = "..\\out\\$(p)\\test.exe"
        debug_working_dir = "..\\out\\$(p)"
        predefine_macros = "_WIN32"
        static_runtime_lib = false
        auto_support_high_dpi = true
    }
}
```

也可用简写形式：`settings.project.result_type = 2`。

| 设置项 | 取值 | 默认 | 说明 |
|--------|------|------|------|
| `result_type` | 1=DLL，2=EXE | 2 (EXE) | 输出类型 |
| `target_platform` | 1=Win32，2=x64 | 1 (Win32) | 目标平台（32/64 位） |
| `out_file_name` | 路径字符串 | - | 自定义输出文件路径；支持 `$(p)`平台、`$(r)`结果类型等变量 |
| `debug_command_line` | 路径字符串 | - | 调试时启动的命令行（DLL 项目常用于指定调用宿主 EXE） |
| `debug_working_dir` | 路径字符串 | - | 调试时的工作目录 |
| `predefine_macros` | 宏文本 | - | 编译时预定义宏，多个用逗号分隔 |
| `static_runtime_lib` | true/false | false（动态链接） | 是否静态链接 C++ 运行库 |
| `auto_support_high_dpi` | true/false | false | 是否自动支持高 DPI（现代应用推荐 true） |

**编译结果目录**：输出默认位于 `..\out\$(平台)\` 等相对路径下。`$(p)` 会被替换为 `win32`/`x64`。

文件名/目录名可使用的环境变量引用（5.3）：`$(p)`平台、`$(r)`结果类型、`$(d)`调试/发布、`$(pf)`项目文件名、`$(lm)`模块链接方式、`$(crt)`运行时库、`$(vs)`VS版本、`$(sp)`解决方案目录、`$(pp)`项目目录、`$(vp)`火山系统目录、`$(tdp)`临时数据目录。

### 7.3 DLL 项目调试配置示例（16.2）

DLL 项目通常需要指定一个调用该 DLL 的 EXE 作为宿主：

```
settings
{
    project
    {
        debug_command_line = "..\\out\\$(p)\\test_call.exe"
        debug_working_dir = "..\\out\\$(p)"
        out_file_name = "..\\out\\$(p)\\test.dll"
        result_type = 1
        target_platform = 1
    }
}
```

### 7.4 root_filter / files 结构要点（15.4）

1. **类库依赖（child_filter / filter）**：通过 `group_file_name` 引用系统类库（`.vgrp` 组文件）。路径以 `*plugins\\` 开头表示火山 IDE 插件目录。
2. **源文件列表（files）**：`file<N>.file_name` 列出项目所有 `.wsv` 源文件，序号从 1 连续编号，`num_files` 为总数。
3. **项目根**：`name` 为项目名称，`type` 固定为 `project`。

| 字段 | 说明 |
|------|------|
| `collapsed` | 是否折叠显示（true/false） |
| `files.num_files` | 类库包含的文件数 |
| `group_file_name` | 类库组文件路径（`*plugins\\` 开头表示 IDE 插件目录） |
| `file<N>.file_name` | 源文件相对路径（如 `src\\main.wsv`），序号从 1 连续编号 |
| `num_files` | 源文件总数 |

### 7.5 常见类库路径速查（15.4）

| 类库 | 路径 | 文件数 |
|------|------|--------|
| 视窗基本类 | `*plugins\vprj_win\classlib\sys\base\base.vgrp` | 16 |
| MFC界面基本类 | `*plugins\vprj_win\classlib\sys\mfc_ui_base\mfc_ui_base.vgrp` | 4 |
| WTL界面基本类 | `*plugins\vprj_win\classlib\sys\wtl_ui_base\wtl_ui_base.vgrp` | 3 |
| JSON数据访问支持 | `*plugins\vprj_win\classlib\sys\json\w_json.vgrp` | 1 |
| Curl网络传输 | `*plugins\vprj_win\classlib\sys\curl\w_curl.vgrp` | 1 |
| SQLite数据库 | `*plugins\vprj_win\classlib\sys\sqlite3\w_sqlite3.vgrp` | 1 |
| ECharts图表组件 | `*plugins\vprj_win\classlib\sys\mfc_ui_echarts\mfc_ui_echarts.vgrp` | 5 |
| MFC版Edge浏览框 | `*plugins\vprj_win\classlib\sys\ui_webview2\mfc_ui_webview2.vgrp` | 1 |

> **易错点**：MFC 与 WTL 界面体系**二选一**，不要同时加入两套界面基本类；混用会导致界面行为异常（V2.5修正：两套体系互斥，不可"同时必需"）。模块路径以 `*` 开头表示相对类库根目录（`plugins\vprj_win\classlib`），写错路径会导致加入后找不到类。

### 7.6 编译配置组合速查（16.5）

| 目标产物 | result_type | target_platform | static_runtime_lib | 说明 |
|---------|-------------|-----------------|--------------------|------|
| 桌面 EXE（单文件分发） | 2 | 1 或 2 | true | 静态链接运行库，目标机器无需装 VC 运行库 |
| 桌面 EXE（动态） | 2 | 1 或 2 | false | 依赖系统运行库，体积小 |
| DLL（供其它程序调用） | 1 | 1 或 2 | 按宿主一致 | 需在导出方法上加 `@视窗.输出` |
| 控制台程序 | 2（`result_type`）+ 控制台标识 | - | - | 启动类继承"程序类" |

**预定义宏组合**（`predefine_macros`，逗号分隔）：常用于控制模块编译分支。例如启用某模块的"新版本"特性时，模块接口常通过宏切换，如 `_VOL_CURL_VER2`（curl 8.15）、`_VOL_SQLITE_VER2`（SQLite 新版本）。多数场景由模块的 `使用新版本` 静态方法自动触发，无需手写宏。

> **易错点**：① `target_platform` 与附属 DLL 位数必须一致（x64 EXE 配 32 位 DLL 会加载失败）；② DLL 项目调试必须配置 `debug_command_line`，否则按 F5 无宿主可启动；③ 修改 `result_type` 后输出目录中的旧产物可能残留，建议清理 `..\out\` 再编译。

### 7.7 源文件命名约定（15.5）

| 文件类别 | 命名模式 | 示例 |
|---------|---------|------|
| 主程序文件 | `src\main.wsv` 或 `main.wsv` | `src\main.wsv` |
| 类文件 | `类_*.wsv` | `类_全局.wsv` |
| 窗口文件 | `窗口_*.wsv` | `窗口_主窗口.wsv` |

## 八、解决方案文件（.vsln）关键字段（15.3）

`.vsln` 是组织管理多个视窗项目的容器（UTF-8 编码），定义项目分组与依赖关系：

```
doc_format_version = 1
name = samples
property.settings.active_project_name = PDF创作

root_filter
{
    child_filter
    {
        filter1
        {
            build_order = 0
            project_file_name = "samples\\tab_demo\\tab_demo.vprj"
            projects_dependent
            type = project
        }
        num_child_filters = 1
    }
    name = root
}
```

| 字段 | 说明 |
|------|------|
| `name` | 解决方案显示名称 |
| `property.settings.active_project_name` | IDE 打开方案时自动激活的项目名称 |
| `filter<N>` | 项目节点或分组节点 |
| `project_file_name` | 项目文件路径（相对解决方案目录，双反斜杠分隔） |
| `build_order` | 构建顺序，数字越小越先编译（当前示例均为 0，按默认顺序） |
| `projects_dependent` | 标记项目间存在依赖关系（无值） |
| `type` | 固定为 `project` |

> **易错点**：项目路径使用 `\\`（双反斜杠）而非 `/`；`num_child_filters` 必须与实际的子项数量一致，否则 IDE 可能解析异常。

## 九、模块定义文件（.vgrp）格式（15.6 + 模块信息）

火山模块 = 模块定义文件（`.vgrp`）+ 所包含的火山源程序文件 + 相关辅助文件（外部库、资源等）。`.vgrp` 为 UTF-8 编码文本文件，头部示例如下：

```
doc_format_version = 1
project_identifier = wutao.vproject.pc.win.1
name = 文本编码转换支持
author = xxx
version = 1
explain = 提供对文字编码转换的支持
file
{
    filter = 编码
    name = 类_编码转换.wsv
}
```

被中括号括住的属性为可选属性，否则为必须提供。

| 名称 | 数据类型 | 可选 | 解释 |
|------|---------|------|------|
| `doc_format_version` | 整数 | 必须 | 文档格式版本，目前必须为 1 |
| `project_identifier` | 文本型 | 必须 | 本模块所支持项目类型的标识符，必须提供且有效。视窗项目类型（版本号为1）的标识符为：wutao.vproject.pc.win.1 |
| `name` | 文本型 | 必须 | 本模块的名称，必须为有效的名称文本 |
| `author` | 文本型 | 可选 | 本模块的作者名称 |
| `version` | 整数 | 可选 | 本模块的版本号 |
| `explain` | 文本型 | 可选 | 本模块的相关注释文本 |
| `discard` | 逻辑型 | 可选 | 表明本模块是否已经被废弃不再使用 |
| `dependence` | 文本型 | 可选 | 本模块正常使用所依赖的其它外部火山模块的定义文件路径，多个用逗号分隔。相对路径相对本模块定义文件目录；以星号字符（`*`）开始表示从项目类型支持插件的类库根目录开始（"classlib"子目录，视窗项目即 `plugins\vprj_win\classlib`）。加入本模块到程序项目中时，这些所依赖外部模块会被自动加入 |
| `unique_mark` | 文本型 | 可选 | 为本模块指定一个唯一性的标记文本，用户程序中只能同时加入一个具有此标记文本的模块 |
| `file` | 块 | 可多个 | 定义一个本模块中的火山源文件 |
| `file.filter` | 文本型 | 可选 | 当前火山源文件所处的过滤器路径名称，路径之间用 `/` 字符分隔。加入本模块到项目中时，该过滤器会被自动创建 |
| `file.name` | 文本型 | 必须 | 源文件路径（相对本模块定义文件目录） |

> **易错点**：`dependence` 中依赖的模块路径写错，会导致该模块加入工程后编译报"找不到类"。以 `*` 开头时相对类库根目录；相对路径则相对模块定义文件所在目录。

**模块管理三步**（15.10：加入 → 依赖 → 使用）：

1. **加入模块**：在 IDE 中把目标 `.vgrp` 加入工程（或在 `.vprj` 的模块 `child_filter` 中引用其 `group_file_name`）。加入后 IDE 会把该模块所有源文件并入工程，模块内定义的类即可被当前项目引用。
2. **自动携带依赖**：`.vgrp` 中的 `dependence` 字段声明了本模块依赖的其它模块，加入时会**自动一并加入**。例如 `dependence = *\sys\json\w_json.vgrp` 表示依赖 JSON 模块。所以手动改工程时，必须同时把 `dependence` 列出的模块也加入，否则报"未找到类"。
3. **按需引用**：使用模块中公开类的类名直接声明变量即可（无需额外 `using`），如 `变量 客户端 <类型 = HP_TCP客户端>`。

| 场景 | 操作 |
|------|------|
| 想用 JSON 功能 | 加入"JSON数据访问支持"模块（自动依赖基础类） |
| 想用 HPSocket 网络 | 加入"HPSocket网络通讯支持" |
| 想用 HTTP 请求 | 加入"Curl网络传输" |
| 某个类找不到 | ① 确认模块已加入 ② 确认 `dependence` 依赖已加入 ③ 确认类名大小写 ④ 确认类为公开类 |
| 加入后编译报"找不到类" | 优先检查 `dependence` 中依赖模块是否齐全（见 18.3） |

## 十、易错点汇总

### 10.1 第11章易错点（11.4）

| 编号 | 易错点 | 涉及章节 | 正确做法 |
|------|--------|---------|----------|
| 1 | 缺少 wsv 文档声明行 | 11.1 | 首非空行必须是 `<火山程序 类型 = "通常" 版本 = 1 />`，否则 IDE 报"文件格式错误" |
| 2 | 调试输出与控制台输出混淆 | 11.1 | 控制台程序用 `标准输出`/`标准输入`（`标准输入字符` 配套）等控制台命令；`调试输出` 结果仅在调试会话可见 |
| 3 | 事件方法命名不规范 | 11.2 | 必须为 `类名_事件名`（如 `时钟_周期事件`）并声明 `<接收事件>` |
| 4 | 时钟周期单位搞错 | 11.2 | `时钟周期` 单位是毫秒，`1000`=每秒一次；设为 `0` 表示不再触发 |
| 5 | 控件声明为静态成员变量 | 11.2 | 静态成员变量不支持自动挂接事件，控件须为普通非静态成员变量 |
| 6 | 格式占位符与参数不匹配 | 11.3 | `%d`(整数)/`%s`(文本) 等占位符类型、个数必须与实际参数一致 |
| 7 | 数值/文本转换边界不清 | 11.3 | 转换失败时返回值接口未明示，先校验再转换；金额精度用 `数值到金融` 或指定小数位，避免浮点误差 |
| 8 | 中文输出乱码 | 11.3 | 输出/网络传输按 UTF-8 处理：`文本到UTF8` / `UTF8到文本` |

> 编号 2 与 11.1（V2.5重写）对照：控制台输出命令以 11.1 为准，使用 `标准输出`/`标准输入`；`调试输出` 结果仅在调试会话可见。

### 10.2 调试/编译易错点（16章）

- `auto_support_high_dpi` 在高分屏机器上默认为 false 时界面会模糊；现代应用建议开启。多显示器缩放不一致时，可通过该设置缓解字体发虚问题。
- `调试检查` 与 `为调试版` 只在调试版生效，发布版中 `为调试版()` 返回假、`调试检查` 不中断；断点行命中时变量可能尚未初始化，先单步到赋值后再看值；多线程场景下，断点命中在哪个线程、哪些变量可见，取决于当前线程上下文。
- 运行库链接方式：动态链接（默认）依赖系统/运行库 DLL，体积小但目标机器需具备对应运行库；静态链接（`static_runtime_lib = true`）将 C++ 运行库静态打进 EXE，单文件分发、目标机器环境不可控时更稳。
- 凡模块声明了 `@视窗.附属文件`（运行时必需的 DLL、资源、数据文件），发布时必须随 EXE 一同复制到目标目录，否则目标机器上会因缺文件而失败。
- 选择 `target_platform = 2`（x64）发布时，附属 DLL 也必须是 64 位版本；同时面向 32/64 位需分别编译并分发两套产物；部分模块仅支持特定位数，发布前核对。

### 10.3 工程文件易错点（15章）

- 缺少 VS 组件时，新建项目或编译会报"工具链缺失"类错误。建议首次安装后先创建一个空视窗项目编译一次，确认工具链配置正确。
- 工程树里看到的每一项都对应工程文件中的一段数据：解决方案 ↔ `.vsln` 根 `root_filter`；项目 ↔ `.vsln` 的 `filter`（`type = project`）→ `.vprj`；模块 ↔ `.vprj` 的 `child_filter` + `group_file_name`（指向 `.vgrp`）；源文件 ↔ `.vprj` 的 `files` 块 `file<N>.file_name`；模块内文件 ↔ `.vgrp` 定义的 `file` 项。
- 手写源码时若不想维护冗长的布局属性，可只写 `<类型 = 按钮 标题 = "确定">` 让设计器自动补全布局；反过来，`@视窗.布局` 的 `pos` 四元组（左、上、宽、高）可直接手改实现精确摆放。跨行属性用 `\r\n` 分隔。
- AI 辅助开发校验清单：首非空行为 `<火山程序 类型 = "通常" 版本 = 1 />`；类/方法名与 `_j.txt` 接口逐一对照，禁止不存在的方法；参数个数/顺序与接口签名一致；属性表 `<>` 配对、属性值含特殊字符加双引号；事件命名 `控件变量名_事件名` + `<接收事件>`；使用的类所属模块已加入工程。
