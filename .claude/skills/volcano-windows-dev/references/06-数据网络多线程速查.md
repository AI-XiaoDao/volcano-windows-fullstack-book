## 1. JSON 数据访问支持（jsoncpp）

`JSON数据访问支持` 模块基于 **jsoncpp（1.9.7）** 封装，包名 `火山视窗.JSON操作`。

| 类 | 说明 |
|----|------|
| `JSON基础类` | JSON 值的基类 |
| `JSON对象类` | JSON 对象（键值对集合） |
| `JSON数组类` | JSON 数组 |
| `JSON类型` | JSON 值类型枚举（空/整数值/无符号整数值/小数值/文本值/逻辑值/键值列表/键值表） |

### 1.1 关键方法

| 类别 | 方法 |
|------|------|
| 创建/清空 | `创建自文本`、`创建自字节集`、`清空`、`是否为空`、`成员数`、`取类型` |
| 取值 | `取文本值`、`取整数值`、`取长整数值`、`取小数值`、`取逻辑值`、`取对象值`、`取数组值`（对象类的"键名称"参数支持 JSON 路径，官方 demo 以 `//` 开头、`.` 分层，如 `//商家.名称`）；数组类另有 `取路径...` 系列（如 `取路径文本值`） |
| 置值 | `置入文本值`、`置入整数值`、`置入长整数值`、`置入小数值`、`置入逻辑值`、`置入对象值`、`置入数组值`（对象类以键名称置入；数组类以"内容 + 插入索引位置@-1"追加成员）；数组类另有按索引 `替换...` 与按路径 `替换路径...` 系列，替换目标索引/路径不存在时直接添加成员 |
| 删除/判断 | `删除成员`、`成员是否存在`（对象类按键名）、`是否存在`/`路径是否存在`（数组类按索引/路径） |
| 输出 | `到可读文本`、`到字节集`、`到文本数组`、`取所有键名` |
| 特性 | `启用顺序输出`、`启用线程安全` |

### 1.2 示例（第8.1.2节）

```火山代码

<火山程序 类型 = "通常" 版本 = 1 />

变量 JSON对象 <类型 = JSON对象类>
变量 JSON文本 <类型 = 文本型>
变量 名称 <类型 = 文本型>
变量 价格 <类型 = 小数>

// 构建 JSON 对象
JSON对象.置入文本值 ("商品名", "机械键盘")
JSON对象.置入小数值 ("价格", 299.5)
JSON对象.置入整数值 ("库存", 100)
JSON文本 = JSON对象.到可读文本 ()

// 从文本解析
JSON对象.创建自文本 (JSON文本)
名称 = JSON对象.取文本值 ("商品名")
价格 = JSON对象.取小数值 ("价格")

// 路径访问嵌套对象（嵌套对象须先单独创建，再置入对象值；路径以 // 开头、. 分层，官方 demo 同此写法）
变量 商家 <类型 = JSON对象类>
商家.创建自文本 ("{\"名称\":\"官方店\"}")
JSON对象.置入对象值 ("商家", 商家)
名称 = JSON对象.取文本值 ("//商家.名称")
```

### 1.3 注意（8.1.2 + 12.1）

- `取文本值` 等取值方法在键不存在时返回空值/默认值，应先 `成员是否存在`（对象类）/`路径是否存在`（数组类）判断；`创建自文本` 解析失败后对象为空，先判 `是否为空`。
- `启用顺序输出` 保持键的写入顺序（jsoncpp 默认按字典序排序）；多线程共享 JSON 对象时 `启用线程安全`。二者均为静态无参方法：`JSON对象类.启用顺序输出 ()` 经预定义宏 `JSON_CPP_SEQUE_OUTPUT` 编译期生效；`JSON对象类.启用线程安全 ()` 经预定义宏 `JSON_CPP_THREAD_SAFE` 编译期生效。
- 键路径写法以官方 demo"`//` 开头、`.` 分层"为准（V2.5修正；12.4 易错点表亦记"键名支持 a.b.c 路径"）。
- 对象/数组方法勿混用：对象类用 `取文本值(键)`/`成员是否存在(键)`；数组类用 `取路径文本值`/`路径是否存在`。

## 2. yyJSON 高性能 JSON 支持库（第8.3节）

由「飞翔的企鹅」封装 yyjson，包名 `火山视窗.JSON支持`，解析速度见长，适合大数据量 JSON。

| 类 | 说明 |
|----|------|
| `YYJSON对象类` / `YYJSON数组类` | 可写对象/数组 |
| `YYJSON只读对象类` / `YYJSON只读数组类` | 只读解析结果 |
| `YYJSON值类型` / `YYJSON值子类型` | 类型枚举 |
| `YYJSON格式化选项` | 格式化输出选项 |

- **只读对象类（解析入口）**：`创建自文本`、`创建自字节集`、`创建自文件`；类型判断 `是否为真/假/逻辑型/无符号整数/整数/长整数/小数/数值/文本/数组/对象/容器/空`；`取类型`、`取子类型`、`取类型描述`；无参转换 `到逻辑值`、`到长整数`、`到整数`、`到小数`、`到文本`；带键取值 `取文本(键)`、`取整数(键)`、`取长整数(键)`、`取小数(键)`、`取逻辑值(键)`、`取对象(键)`、`取数组(键)`；路径取值 `取路径文本/整数/长整数/小数/逻辑型/对象/数组/内容`（路径以 `/` 开头，如 `/user/0`）；`取键值数`、`取成员数`、`到可读文本`、`到数组`。
- **只读数组类**：无创建方法，须先 `只读对象类.创建自文本` 再 `到数组 ()` 取得；`取成员`、`取整数/取长整数/取小数/取文本 (成员索引)`、`取首/尾成员`、`取成员数`、`到可读文本`；嵌入式 `枚举循环 () { ... 取枚举值 () ... }` 遍历。
- **可写对象类**：`创建值自空值/逻辑值/长整数/整数/小数/文本/文件`；`加入空/逻辑值/长整数/整数/小数/文本成员 (键, 值)`；`加入成员`、`加入数组成员`、`缓存并加入成员`；`删除成员`、`清空`。
- **可写数组类**：`创建自逻辑型/长整数/小数/字节/短整数/整数/文本数据`；`加入空/逻辑值/长整数/整数/小数/文本成员 (值)`、`加入新成员`；`插入成员`、`插入成员到首部`、`替换成员`（含 `缓存并...` 系列）、`删除成员`、`删除首部/尾部/范围成员`、`清空`、`翻转`、`取成员`、`取首/尾成员`。

### 2.1 示例（第8.3节 yyjson 快速解析）

```火山代码

<火山程序 类型 = "通常" 版本 = 1 />

变量 只读对象 <类型 = YYJSON只读对象类>
变量 只读数组 <类型 = YYJSON只读数组类>
变量 成员 <类型 = YYJSON只读对象类>

// 解析 JSON 数组文本（只读数组类无创建方法，须先解析到只读对象再转数组）
只读对象.创建自文本 ("[{\"id\":1},{\"id\":2}]")
只读数组 = 只读对象.到数组 ()
只读数组.枚举循环 ()
{
    成员 = 只读数组.取枚举值 ()   // 取枚举值() 仅限在 枚举循环() 子语句体内使用
    调试输出 (成员.取整数 ("id"))   // 带键取值用 取整数(键)；到整数() 为无参转换
}
```

> 易错点：解析 JSON 文本统一先 `创建自文本` 到只读对象（或对象类），再经 `到数组 ()` 转数组；**yyjson 解析结果为只读视图，修改数据须通过可写对象/可写数组类**；带键取值用 `取整数 (键)` 等 `取...` 系列，`到整数 ()` 等 `到...` 是无参自身转换；`枚举循环 ()` 须配合循环体内 `取枚举值 ()`（仅限子语句体内使用）。一般业务场景 jsoncpp 的 JSON对象类更直观。

## 3. XML 数据访问支持（pugixml，第8.2节）

`XML数据访问支持` 模块封装 pugixml，包名 `火山视窗.XML操作`。

| 类 | 说明 |
|----|------|
| `XML文档类` | XML 文档根对象 |
| `XML节点类` | 节点，提供遍历与增删改查 |
| `XML属性类` | 节点属性 |
| `XML节点集` | 节点集合 |
| `XML合成器类` | 从零构造 XML 文档 |
| `XML枚举事件接收器` | 枚举节点时接收事件 |
| `XML节点类型` / `XML节点值` / `XML属性基础类` | 类型/值枚举与基础类 |

### 3.1 关键方法

- **XML文档类**：`从文本创建`、`从文件创建`、`从内存创建`、`从字节集创建`、`从资源创建`、`到文本`、`到字节集`、`保存到文件`、`枚举所有节点`、`取节点`、`取节点集`、`取路径属性`；路径取值方法 `取文本值`/`取整数值`/`取长整数值`/`取小数值`/`取逻辑值`/`取变整数值`（参数为 XPath 路径表达式，属性路径写作 `根节点/@属性名`，官方 demo 如 `文档.取整数值 ("根节点/@整数")`）。
- **XML节点类**：`取节点类型`、`取父节点`、`取首/尾节点`、`取下一个/上一个节点`、`取子节点`、`枚举子节点`、`枚举属性`、`取属性`、`取首/尾属性`、`置节点名称`、`添加属性到尾部/头部/指定属性前后`、`添加节点到头部/尾部/前后`、`添加指定类型节点到尾部/头部`、`删除属性`、`删除子节点`、`取元素节点值`、`取元素节点名称`、`取数据节点值`、`置数据节点值`。
- **XML节点值类**（节点文本内容读写，须先经 `取元素节点值 ()` 取得后再调用）：`取文本值`、`取整数值`、`取长整数值`、`取小数值`、`取逻辑值`、`取变整数值`、`置入文本值`、`置入整数值`、`置入长整数值`、`置入小数值`、`置入逻辑值`、`置入变整数`。官方 demo 写法 `文档.取节点 ("新名称").取元素节点值 ().置入文本值 ("修改节点值")`。

### 3.2 示例（第8.2.2节）

```火山代码

<火山程序 类型 = "通常" 版本 = 1 />

变量 文档 <类型 = XML文档类>
变量 根节点 <类型 = XML节点类>
变量 子节点 <类型 = XML节点类>
变量 节点名称 <类型 = 文本型>

文档.从文件创建 ("C:\\config\\settings.xml")
根节点 = 文档.取子节点 ("config")
子节点 = 根节点.取子节点 ("name")
节点名称 = 子节点.取元素节点值 ().取文本值 ()   // 节点文本值须先经 取元素节点值() 取得 XML节点值 再读取
调试输出 (节点名称)
```

### 3.3 注意

- XML 对大小写敏感，节点/属性名需精确匹配；`从文件创建` 失败时文档对象为空，应先判断是否创建成功。
- `XML合成器类` 适合程序化生成 XML：`开始节点`、`添加子节点`、`置节点内容`、`导出XML文档`。

## 4. 高性能键值表（MMKV，第8.4节）

`数据处理支持1` 模块中的 `高性能键值表` 基于腾讯开源 MMKV，包名 `火山.视窗.高性能键值表`。适合本地持久化轻量配置、缓存。

| 类 | 说明 |
|----|------|
| `高性能键值表` | 核心键值存储 |
| `高性能文本数组类` | 文本数组辅助 |
| `高性能键值表事件` / `高性能键值表日志` | 事件与日志回调 |

| 类别 | 方法 |
|------|------|
| 打开关闭 | `高性能键值表.置保存路径 (目录)`（**静态**，须类名调用，使用前必须设置一次）、`打开 (表名称@默认表, 模式@单进程模式, 加密密码@可空)`、`关闭` |
| 查询 | `取键数量`、`取总大小`、`取实际大小`（均返回**长整数**）、`是否存在表`、`是否存在键`、`取所有键名 (结果数组)`（结果数组为**出参** `高性能文本数组类`） |
| 删除 | `删除键`、`清空`、`清空缓存` |
| 同步 | `锁定`、`解锁`（多线程访问同一表的场景） |
| 读写 | `置入逻辑值/整数值/长整数值/小数值/文本值/字节集/数组值`（键, 值），对应 `取逻辑值/整数值/长整数值/小数值/文本值/字节集/数组值`（键）；`取数组值 (键, 结果数组)` 结果为**出参** |
| 事件（属 `高性能键值表事件` 类） | `启用事件 (高性能键值表事件.启用日志 + 启用内容变化 + 启用遇到错误)`；接收事件 `内容变化 (表名称)`、`遇到错误 (表名称, 错误类型)`、`日志内容 (日志等级, 文件名称, 行号, 函数名称, 消息内容)` |

### 4.1 示例（第8.4.2节）

```火山代码

<火山程序 类型 = "通常" 版本 = 1 />

变量 键值表 <类型 = 高性能键值表>
变量 用户名 <类型 = 文本型>

// 置保存路径 为静态方法，全局只需设置一次（须在打开前调用）
高性能键值表.置保存路径 ("C:\\appdata\\kv")
键值表.打开 ("userdata")
键值表.置入文本值 ("username", "张三")
键值表.置入整数值 ("loginCount", 5)

用户名 = 键值表.取文本值 ("username")
调试输出 (用户名)
键值表.关闭 ()
```

### 4.2 注意

- `置保存路径` 为静态方法，须以 `高性能键值表.置保存路径 (目录)` 类名调用，打开任何键值表之前设置一次（官方 demo 注释"全局初始化，只需要设置一次"）。
- `打开` 表名称为空时打开默认表；模式参数为 `高性能键值表.单进程模式`/`高性能键值表.多进程模式`；加密密码参数可空。
- `取数组值`/`取所有键名` 均为**出参**，须先定义 `高性能文本数组类` 变量传入；`高性能文本数组类` 另有 `添加文本数组 (文本数组类)`。
- 事件须定义 `高性能键值表事件` 类型变量（官方 demo 注释"全局只能定义一个"）并调用 `启用事件 (…)`；日志等级为 `高性能键值表日志` 枚举（`调试/信息/警告/错误/无`）。
- 键值表适用于小型数据，大数据集合建议使用数据库（第9章）。

## 5. 压缩解压模块（第8.5节）

| 模块 | 用途 | 核心类 |
|------|------|--------|
| `libzip压缩解压` | zip 文件压缩解压 | `ZIP压缩解压类` 等 9 类 |
| `zlib压缩解压` | 数据通用压缩解压（流式/内存数据） | `压缩解压类` |
| `RAR文件解压缩支持` | RAR 压缩文件格式访问/处理 | `RAR文件解压类` 等 3 类 |

典型场景：**libzip** 创建/读取标准 zip 归档；**zlib** 对字节集/流通用压缩（网络传输前压缩）；**unrar** 解压 RAR 格式文件。

### 5.1 libzip 压缩示例（第8.5节）

```火山代码

<火山程序 类型 = "通常" 版本 = 1 />

变量 ZIP对象 <类型 = ZIP压缩解压类>
变量 错误码 <类型 = 整数>

// 创建压缩包：位或组合"创建模式 + 截断模式"（已存在则重建），成功返回 0
错误码 = ZIP对象.打开文件 ("C:\\out\\archive.zip", 位或 (ZIP打开模式.创建模式, ZIP打开模式.截断模式))
如果 (错误码 != 0)
{
    调试输出 ("打开失败：" + ZIP对象.取错误文本 (错误码))
    返回
}
ZIP对象.添加文件 ("report.pdf", "C:\\data\\report.pdf", ZIP压缩方法.DEFLATE压缩, , , )
ZIP对象.关闭 ()   // 保存所有修改并关闭

// 读取：只读模式打开后整体解压到目录
错误码 = ZIP对象.打开文件 ("C:\\out\\archive.zip", ZIP打开模式.只读模式)
如果 (错误码 == 0)
{
    ZIP对象.解压全部 ("C:\\out\\unpack")
    ZIP对象.关闭 ()
}
```

### 5.2 注意

- libzip 打开模式支持 `位或` 组合（`ZIP打开模式.创建模式 + ZIP打开模式.截断模式` 新建/重建压缩包）；`打开文件`/`添加文件`/`添加数据`/`关闭`/`解压到文件` 均返回错误码（成功返回 0），失败用 `取错误文本 (错误码)` 获取描述；`ZIP错误码` 常量含 `密码错误`/`无密码`/`已关闭`/`CRC校验失败` 等。
- `添加文件 (条目名, 文件名, 压缩方法, 加密方法, 密码, ...)` 从第 3 参起可跳参留空位，加密可选 `ZIP加密方法.AES128/192/256`；`添加数据 (条目名, 字节集, ...)` 从内存字节集加入条目。
- `取所有条目 (出参 ZIP条目集类)` 配合 `条目集.枚举循环 ()`/`取枚举值 ()` 枚举条目，条目信息含 `条目名`/`加密方法`/`压缩前尺寸`/`压缩后尺寸`/`最后修改时间`/`CRC`。
- 解压路径注意防路径穿越（文件名含 `..`）。

## 6. 文本编码转换（libiconv，第8.6节）

`文本编码转换支持` 模块：`编码转换类`/`编码转换方式类`/`编码类型`，编码名称取常量类 `编码类型`（GB2312/GBK/GB18030/BIG5/UTF_8/UCS_2/UCS_2LE/EUC_JP/SHIFT_JIS 等，`编码类型.UTF_8` 初值 "UTF-8"）。

**静态 4 方法（均返回逻辑型、`编码转换类.` 静态调用）**：

| 方法 | 签名 |
|------|------|
| `编码转换` | `编码转换 (欲转换数据:字节集类, 转换前编码:文本型, 转换后编码:文本型, 结果变量:字节集类)` |

- `执行SQL语句` 返回**逻辑型**（执行是否成功），成功后经 `取记录集 ()` 获取记录集；`取临时记录集 ()` 占用内存更低、效率更高，但不支持 `到指定行 ()`。
- 记录集导航：MySQL 记录集用 `到下一行 (行:长整数)`/`到指定行 (行:长整数)` 定位（**MySQL 记录集类无 `到首记录`**）。
- `转义SQL语句` 用于拼接含引号的动态 SQL 时转义，防止注入；字符集与服务端一致（`置字符集`），否则中文乱码。
- `使用新版本` 为编译期方法，任意执行流调用一次即启用 MySQL 8.0.40 编译（否则用 6.1.11）；`SSL模式`、`连接超时` 等属性须在 `连接 ()` 之前调用才生效。
- 高并发/多线程场景用 `Mysql连接池类` 管理连接。

### 12.4 本章易错点总结（第12章）

| 编号 | 易错点 | 正确做法 |
|------|--------|---------|
| 1 | JSON 对象/数组方法混用 | 对象类用 `取文本值(键)`/`成员是否存在(键)`；数组类用 `取路径文本值`/`路径是否存在` |

| 4 | 未判断匹配是否成功 | 先判断 `正则.匹配 (内容, 表达式)` 返回的逻辑型值（或 `是否存在匹配 ()`）再取 `取子匹配文本 (0)`/子组 |
| 5 | SQL 字符串拼接注入 | 一律参数化：`?` 占位符配合 `置...参数数据`，禁止直接拼接用户输入 |
| 6 | 记录集导航方式错误 | 逐行读取用 `执行语句() == SQLite执行结果.下一行就绪` 判断，记录集无"到下一行" |
| 7 | 数据库资源未释放 | 记录集/连接用后调用 `释放`；失败用 `取最近错误描述` 定位 |
| 8 | JSON1/FTS5 特性不可用 | 需要 JSON1/FTS5 全文检索时先调用 `使用新版本` |

### 13.4 PULL/PACK/UDP 模型

| 模型 | 说明 |
|------|------|
| TCP（RAW） | 数据进入事件提供"已接收数据 + 已接收长度"，原样交付，消息边界由应用处理 |
| PULL | 事件只提供"数据长度"，原始字节写入内部缓冲区；用户累计长度，凑够包长后调用 `抓取数据(连接ID, 缓冲区, 数据长度)`/`窥探数据(连接ID, 缓冲区, 数据长度)`（返回 `HP数据抓取结果`，窥探不取出缓冲区） |
| PACK | 内部按包头自动组包，**仅当接收完整数据包后才触发**数据进入事件；`最大包尺寸` 有效上限 4194303（0x3FFFFF）字节、默认 262144（0x40000）；`自定义包头标识` 为短整数，取值 0~1023，默认 0（为 0 时不校验包头） |
| UDP | 无连接数据报文通信，支持广播与 ARQ（自动重传）可靠模式 |

类：PULL `HP_PULL客户端`/`HP_PULL安全客户端`/`HP_PULL服务器`/`HP_PULL安全服务器`；PACK `HP_PACK客户端`/`HP_PACK安全客户端`/`HP_PACK服务器`/`HP_PACK安全服务器`；UDP `HP_UDP客户端`/`HP_UDP广播器`/`HP_UDP节点`/`HP_UDP_ARQ客户端`/`HP_UDP服务器`。

### 13.6 注意事项（13.1.5 + 9.6 通用）

1. 对象声明后必须调用 `启动` 才真正开始工作；客户端 `启动` 第三参数（异步连接）为真时，连接结果在 `连接完成` 事件中返回。
2. **网络数据编码**：`发送数据` 接收 `字节集类`，发送文本必须先 `文本到字节集()` 转换；接收后 `字节集到文本()` 还原。
3. **客户管理（服务端）**：`HP_TCP服务器` 本身不提供客户枚举方法，须自行维护客户列表（13.1 用 `客户信息数组类` + `列表框`）；`客户离开` 时必须同步清理数组与列表框，否则索引错乱。
4. **IP 地址获取**：`HPSocket类.取主机IP地址().取成员(0)` 取第一个 IP，多网卡环境下可能是虚拟网卡地址，实际部署应让用户选择或遍历所有 IP。
5. **端口号**：13.1 示例固定使用端口 999，注意端口冲突；客户端与服务端端口必须一致。
6. **事件命名规范**：事件接收方法名必须为 `类名_事件名` 格式（如 `HP_TCP客户端_数据进入`、`HP_TCP服务器_客户进入`），且必须声明 `<接收事件>`，否则事件不会触发。
7. **资源释放**：窗口销毁时必须显式调用 `停止()`，否则端口占用或资源泄漏；所有事件中的 `连接ID`（类型 `变整数`）用于标识特定连接。
8. **文本换行**：编辑框多行拼接必须用 `\r\n`，仅用 `\n` 在视窗控件中不会正确换行。
9. 安全类（`HP_TCP安全客户端/服务器` 等）启用 SSL 前必须先调用 `初始化SSL环境`（或 `初始化SSL环境_内存`）成功后再 `启动`，部署时确保 OpenSSL 相关 DLL 到位；SSL 安全类需额外配置 SSL 证书与验证模式（`HPSSL验证模式`）。

### 14.3 注意事项（13.2.2 + 13.3）

1. **UI 线程安全（最高优先级）**：Windows 窗口控件**不是**线程安全的；子线程直接操作 UI 控件是教学简化写法，生产环境应使用主线程处理器（发送通知/投递通知/接收通知事件机制）将 UI 更新投递回主线程，否则可能崩溃、死锁或界面闪烁。
2. **线程退出必须及时**：`线程是否被通知退出()`/`是否需要退出()` 返回真后线程函数必须尽快返回，否则 `通知并等待线程退出()` 会长时间阻塞调用方；必须在循环中频繁调用（建议 100~500ms 间隔）。
3. **窗口销毁顺序**：`_将被销毁` 事件中必须先退出所有线程再销毁资源；`我的线程1` 作为成员变量会在对象析构时自动停止，`线程状态1/2` 不会，需显式调用。
4. **静态方法限制**：`线程主函数` 声明为 `静态`，不能访问实例成员变量，必须通过 `线程状态对象` 传递所需数据（`置用户对象1`）。
5. **用户值类型**：`置用户值`/`取用户值` 类型为变整数（整数可隐式转换为变整数）；传递复杂数据用 `置用户对象1`。
6. `循环判断首() { ... } 循环判断尾(条件)` 保证循环体至少执行一次，适合"先执行再检查"的场景。

## 15. 网络聊天室（第14章，内置 `客户`/`服务器` 类）

`chat_client` 与 `chat_server` 基于火山视窗内置网络组件（`客户` 与 `服务器` 类）实现多人实时文字通信。与 13.1 的 HPSocket 相比：内置组件接口更简洁（`客户.发送数据` 可直接传文本），HPSocket 功能更丰富、性能更高。

| 功能 | 说明 |
|------|------|
| 服务端监听 | 启动后自动监听默认端口（19730），等待客户端连接 |
| 客户进入/离开 | 服务端实时显示在线客户 IP 地址与端口列表 |
| 服务端断开客户 | 选中某客户并强制断开连接 |
| 客户端连接/断开 | 输入服务端地址和端口，点击按钮连接或断开 |
| 消息收发 | 客户端发送文本消息给服务端，服务端自动**群发**给所有在线客户 |
| 连接状态管理 | 客户端根据连接状态自动切换按钮文字（"连接服务器"/"断开服务器"）并启用/禁用发送按钮 |
| 界面状态同步 | `更新状态` 辅助方法统一管理按钮文字和禁止属性 |

**关键方法**：`服务器1.开始监听 ()`；`服务器1.断开客户 (客户地址文本)`；`服务器1.发送数据 (接收客户地址, 最长等待时间, 所欲发送的所有数据)`——第1参数空文本=广播所有已连接客户，第2参数单位秒（-1=无限等待，省略默认 -1），第3参数通用型可直接传文本或字节集；`客户1.连接 (地址, 端口)`；`客户1.断开连接 ()`；`客户1.是否已连接 ()`；`客户1.发送数据 (文本)`（直接接收文本型内容，与 HPSocket `发送数据(字节集)` 不同）；`信息编辑框.加入文本行 (文本)` 自动追加一行（内部已处理换行）。

**事件**（均为 `类名_事件名` + `<接收事件>`）：`服务器_客户进入 (所进入客户地址:文本型)`（格式为 "IP地址 + 端口"）、`服务器_客户离开 (所离开客户地址:文本型)`、`服务器_数据到达 (客户地址:文本型, 所接收到的数据:字节集类)`、`客户_数据到达 (所接收到的数据:字节集类)`、`客户_连接断开`。

### 15.3 注意（14.1 + 14.2）

1. **端口号一致性**：客户端端口编辑框（默认 `19730`，`输入方式 = 输入整数`）必须与服务端监听端口匹配，修改后两端同步。
2. **群发参数**：`服务器1.发送数据 ("", 1, data)` 即"向所有客户发送，每客户最长等待1秒"；群发会发给所有人（包括发送者）。
3. **客户离开遍历**：`服务器_客户离开` 中删除项目后必须 `跳出循环`——项目数已减少，继续遍历会访问已不存在的索引。
4. **连接状态管理**：在 `客户_连接断开` 事件中调用 `更新状态()`（而非按钮事件中）——连接断开可能由服务端主动断开或网络异常触发。
5. **多次连接保护**：连接前先 `是否已连接()` 判断，已连接则先 `断开连接()` 再重连，避免重复连接或资源泄漏。
6. **发送失败反馈**：`发送数据` 返回假时提示用户，不要让失败静默发生；服务端群发前应检查编辑框是否为空。
