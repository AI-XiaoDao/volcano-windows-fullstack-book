# 知识库使用指引（核验方法）

> 本文档说明如何在本项目知识库中定位、读取、解码火山接口文件，并用原文证据核验 API——这是"禁止编造 API"红线的落地工具。

## 一、知识库文件构成

| 目录 | 内容 | 编码情况 |
|------|------|---------|
| `视窗模块源码wsv格式AI知识库/` | 389 对模块文件（`*_j.txt` 接口 + `*_p.txt` 源码），约 97 个模块显示名 | `_j.txt` 均为 UTF-8 编码，但大多数文件（约 79%）存在键名前缀污染，必须按第五节以键值匹配方式提取，不能直接整文件解析 JSON；`_p.txt` 多为双重编码 |
| `视窗wsv源码demoAI知识库/` | 254 对官方示例（`*_j.txt` 接口 + `*_p.txt` 源码） | 同上 |
| `火山视窗AI辅助文件/` | 3 份权威文档（普通 UTF-8） | 封装语法手册 / 模块信息 / 项目文件格式技术规范 |
| 项目根 | `火山wsv文件格式标准.md`（普通 UTF-8） | wsv 语法唯一权威 |

## 二、接口文件名约定与模块定位

接口文件名形如：`sys_<分组目录>_<模块名>_j.txt`，例如：

| 文件名 | 模块显示名 | 包名 | .vgrp 路径（按官方模块信息） |
|--------|-----------|------|------------------------------|
| `sys_mfc_ui_base_w_mfc_base_control_j.txt` | MFC界面基本类（子模块） | 火山.MFC界面.基本 | `*\sys\mfc_ui_base\mfc_ui_base.vgrp` |
| `sys_hp_socket_w_hp_socket_client_j.txt` | HPSocket网络通讯支持 | 火山.视窗.网络 | `*\sys\hp_socket\w_hp_socket.vgrp` |
| `sys_json_w_json_j.txt` | JSON数据访问支持 | 火山视窗.JSON操作 | `*\sys\json\w_json.vgrp` |
| `sys_data_oper1_w_mmkv_j.txt` | 数据处理支持1（内含 w_mmkv.v） | 火山.视窗.高性能键值表 | `*\sys\data_oper1\w_date_oper1.vgrp` |

**定位步骤**：
1. 查模块显示名/用途 → `火山视窗AI辅助文件/火山视窗模块信息.md`（85 个官方模块的 .vgrp 路径总表）；
2. 用 Glob 在知识库目录按关键字找文件（如 `*webview2*`）；
3. 打开 `*_j.txt` 头部确认："访问本程序中的接口需要引用模块\<显示名\>" 与 `"package name"`。

> 注意：接口文件名最后一段是**模块内源文件名**（如 `w_Pugixml.v`、`w_CSerialPort.v`、`w_mmkv.v`），不是 .vgrp 定义文件名。.vgrp 路径一律以《火山视窗模块信息.md》为准（如 XML 模块是 `*\sys\xml\w_xml.vgrp` 而非 `w_Pugixml.vgrp`）。

## 三、`_j.txt` 接口 JSON 结构

```json
{
  "file description": "...",
  "package name": "火山.基本",
  "classes": [
    { "class name": "对象类",
      "base class": "...",
      "@别名": "...",
      "comment": "...",
      "methods": [
        { "method name": "取对象类输出名",
          "comment": "...",
          "type": "property getter | property setter | event",   // 无此字段=普通方法
          "static": true,                                        // 有=静态
          "data type": "文本型",                                  // 方法返回类型/属性类型/事件接收方法返回类型
          "result comment": "...",
          "@默认值": "0", "@嵌入式方法": "\"\"", "@禁止流程检查": "真", "@视窗.设置时机": "组件创建前",
          "parameters": [ { "parameter name": "...", "data type": "...", "comment": "...", "@默认值": "..." } ]
        }
      ],
      "variables": [ { "variable name": "...", "data type": "..." } ]
    },
    { "class name": "某常量类", "@常量类": "整数", "constants": [ { "constant name": "...", "initial value": "..." } ] }
  ]
}
```

**核验规则**：
- 类存在性：Grep `"class name": "类名"`；
- 方法存在性：Grep `"method name": "方法名"` 并确认位于正确的类区间（类的起始行到下一类的 `"class name"` 之间）；
- 常量核验：Grep `"constant name"` 并确认位于正确的类区间（类的起始行到下一类的 `"class name"` 之间）；
- 签名：核对 parameters 顺序/名称/类型/`@默认值` 与 `data type`（返回类型）；
- 属性读/写：`"type": "property getter"`（可读）与 `"property setter"`（可写）是分开的两条记录，仅写的属性不能作为取值表达式；
- 事件：`"type": "event"`，其 `data type` 为接收方法的返回类型（整数），parameters 为事件参数。

## 四、双重编码解码（`*_p.txt` 源码）

多数 `_p.txt` 正文是"UTF-8 字节被当作字符再编码"产生的乱码，解码方法（PowerShell）：

```powershell
$t = [System.IO.File]::ReadAllText($path, [System.Text.Encoding]::UTF8)
# 方案1：读UTF-8 → Unicode.GetBytes 取回原字节 → UTF8.GetString 解码
$final = [System.Text.Encoding]::UTF8.GetString([System.Text.Encoding]::Unicode.GetBytes($t))
```

> 本知识库的 `_p.txt` 均为方案 1 模式；"逐字符减 0xE000 还原字节"的 PUA 映射方案仅见于个别外部文件，本知识库不存在该损坏模式。

**判据**：解码成功时能看到 `类`/`方法`/`变量`/`包` 等 wsv 成员定义行。解码失败不要强猜——改用同名的 `_j.txt`（接口描述与源码一致）或权威文档。

## 五、键名前缀污染

部分接口文件每行开头夹带乱码/重复片段（如行首出现其它成员的值），但 `"class name"`、`"method name"` 等 JSON 键值本身完好。提取时**以键值匹配为准**，不要被行首乱码干扰；必要时用 Grep 的 `-o` 只取匹配片段。

## 六、官方 demo 的使用

- `*_j.txt`：demo 的公开接口（启动类/公开类），可直接读；
- `*_p.txt`：demo 源码（解码后可见全部类与事件接收方法）；
- 事件命名约定以 demo 为准：书中第 11~14 章对应的 17 个示例共 68 个接收方法全部为 `类名_事件名`（官方 demo 全库 981 处接收方法定义、418 个不同方法名亦全部为此形式）（如 `按钮_被单击`、`时钟_周期事件`、`服务器_客户进入`），方法体内用 `如果 (成员变量 == 来源对象)` 区分来源；
- 各章示例代码与 demo 的对应关系见《火山视窗全栈开发技能书》第三篇（第 11~14 章）。

## 七、核验工作流（对任何待核验内容）

1. **列清单**：提取待核验文本中全部 API 引用（类/方法/属性/事件/常量/参数）；
2. **逐项 Grep**：在对应模块 `_j.txt` 中检索，确认存在与签名一致；
3. **全库反查**：对可疑名字在知识库全目录 Grep——只命中输出文档（书自身）即编造；
4. **权威文档终裁**：语法/关键字/属性名以《封装语法手册》《wsv 格式标准》为准；模块路径以《模块信息》为准；
5. **对抗式复核**：换一个角度尝试反驳"这真是错吗"，拿不出原文证据的候选一律放弃。

> 本指引与《火山视窗全栈开发技能书》配套；版本差异时以本机实际安装模块的接口为准。
